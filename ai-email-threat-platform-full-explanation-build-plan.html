AI-Powered Email Threat Detection & Forensic Intelligence Platform

Plain-English explanation of what you are building, every technology used, every module explained, and a full phase-by-phase build plan.

In one sentence: You are building a website where a user can upload a suspicious email file, and the system automatically investigates it — like a digital forensics lab — telling you whether it's a phishing attack, who sent it, what fake links it contains, where the mail server is located, and producing a PDF investigation report.

Think of it this way: Just like a forensic scientist examines a crime scene and produces an evidence report, your platform examines a suspicious email and produces a digital evidence report. Instead of fingerprints, you're looking at email headers, authentication stamps, suspicious links, and IP addresses.

How the System Works (The Flow)

Every time someone uploads an email, it passes through this chain of steps:

Upload .eml→ Parse Email→ Header Forensics→ SPF/DKIM/DMARC→ AI/ML Detection→ URL Analysis→ IP Intelligence→ Risk Score→ Dashboard→ PDF Report

All 13 Modules — What Each One Does

1
Email Ingestion & Parsing
Accepts the .eml file upload and breaks it apart into its components — sender, recipient, subject, headers, body text, URLs, and attachments. Like opening an envelope and separating the letter from the envelope, stamp, and postmark.
2
Email Header Forensics
Email headers are invisible metadata — like the postal routing stamps on a package. This module reads them to find anomalies: does the "From" address match the "Reply-To"? Did the email travel through unexpected servers? Are there signs of forgery?
3
SPF / DKIM / DMARC Analysis
These are three email authentication protocols. SPF checks if the sending server is authorized. DKIM checks if the email was digitally signed and not tampered with. DMARC ties them together with a policy. A FAIL on any of these is a red flag — like a package arriving without the official security seal.
4
AI / ML Email Threat Detection
This is the "brain" of the system. A machine-learning model trained on thousands of phishing and legitimate emails reads the email body and detects patterns like urgency ("Act now!"), credential requests ("Enter your password"), impersonation language, and social engineering. It classifies the email as LEGITIMATE, SUSPICIOUS, PHISHING, etc.
5
URL Analysis
Extracts every link from the email and checks it. Is the domain a lookalike (e.g., "secure-bank-Iogin.com" with a capital I instead of lowercase L)? Does it use suspicious keywords like "verify", "login", "password"? Is it an IP address disguised as a link? All this is flagged.
6
Domain Intelligence
Looks up DNS records for suspicious domains — like looking up a company's registered address. Finds who owns the domain, what mail servers it uses, what IP addresses it points to. This helps reveal fake domains that were just registered for a one-time attack.
7
IP & Infrastructure Intelligence
Extracts IP addresses from the email's routing path (the "Received" headers). For each IP, it fetches the approximate country, region, ISP, and ASN (autonomous system number — basically which network company owns that IP block). This maps the mail infrastructure, not the attacker's home address.
8
Threat Intelligence & Correlation
Connects the dots: if the email's suspicious URL and the domain in the "From" header both resolve to the same IP address, that's a strong correlated signal. This module builds a graph of relationships between all indicators found.
9
Threat Risk Scoring
Combines all signals into a single score out of 100. Each module contributes points. The system also explains why — listing the exact indicators that drove the score up. This makes the AI "explainable", which is critical in security investigations.
10
Investigation Dashboard
The main screen analysts see after analysis — a clean web page showing risk score, classification, sender info, authentication results, IP intelligence, and threat indicators all in one place. Think of it as the "crime board" in detective shows.
11
Investigation Graph
A visual network diagram showing how indicators are connected — email → domain → IP → ISP. Makes it easy to see at a glance how the infrastructure is linked. Built using a graph visualization library.
12
Evidence Preservation
When the email is uploaded, the system calculates its SHA-256 hash — a unique digital fingerprint of the file. If the file is tampered with later, the hash will change, proving tampering. Stores Case ID, timestamps, and analysis results for chain-of-custody purposes.
13
Forensic PDF Report Generation
With one click, generates a formal PDF document containing every finding — case info, authentication results, AI classification, URL analysis, IP intelligence, threat indicators, and a written conclusion. This report can be submitted as documentation in an investigation.

Technology Stack — What Each Tool Is & Why It's Used

TechnologyWhat it isWhy it's used here
React.js A JavaScript library for building web user interfaces. Powers the interactive frontend — the dashboard, upload page, graphs, and report button. It re-renders only what changes, making the UI fast.
Tailwind CSS A utility-based CSS framework for styling web pages. Lets you build a professional-looking UI quickly without writing custom CSS files. Classes like text-red-600 or p-4 style elements inline.
Python + FastAPI Python is the programming language. FastAPI is a modern web framework for building APIs. The backend — handles file uploads, runs all analysis, talks to the database, calls external APIs. FastAPI is chosen because it's fast, auto-generates documentation, and works great with Python ML libraries.
Scikit-learn Python's most popular machine learning library. Trains and runs the phishing classification model. Algorithms like Naive Bayes, Random Forest, or SVM can classify emails based on features extracted from the text.
Python NLP Libraries (NLTK / spaCy) Tools for processing and understanding human language in Python. Cleans the email body text, extracts keywords, detects urgency/threat language patterns, and converts text into numbers that ML models can process.
Python email library Python's built-in library for parsing email files. Reads the raw .eml file and splits it into headers, body, attachments, etc. It handles all the messy MIME encoding that real emails use.
MongoDB A NoSQL database that stores data as flexible JSON-like documents. Stores analysis results, case information, evidence hashes, and historical records. NoSQL is ideal here because each email's analysis output has a different structure.
REST APIs A standard way for the frontend and backend to communicate over HTTP. The React frontend sends requests to FastAPI endpoints (e.g., POST /analyze) and receives JSON results to display. This separation means frontend and backend can be developed independently.
IP Geolocation API (ip-api / IPinfo) A free/paid web service that returns location and ISP data for an IP address. The system calls this API with each extracted IP address and gets back approximate country, region, ISP, and ASN. No need to build this database yourself.
dnspython A Python library for making DNS queries. Looks up DNS records (A, MX, NS, TXT) for suspicious domains to get their IP addresses, mail servers, and SPF records.
Leaflet + OpenStreetMap An open-source JavaScript map library using free map tiles. Renders the IP geolocation on an interactive map on the dashboard. No Google Maps API key required — completely free.
Cytoscape.js / React Flow JavaScript libraries for drawing interactive network/graph diagrams. Draws the investigation graph showing how email → domain → IP → ISP nodes are connected.
ReportLab A Python library for generating PDF files programmatically. Builds the forensic PDF report on the server side from the analysis data, with proper formatting, sections, and tables.
JWT (JSON Web Tokens) A standard for securely transmitting user identity information. Handles authentication — when a user logs in, the server issues a JWT token. The frontend sends this token with every request to prove who the user is.
Vercel A free cloud platform for deploying frontend web apps. Deploy the React frontend for free. Every push to GitHub auto-deploys. Gives you a public URL instantly.
Render A free cloud platform for deploying backend services. Hosts the FastAPI backend. Free tier works well for a college project demonstration.

Important Limitation Built Into the Project

The system is an investigative assistance tool, NOT an attribution system.
  • It will NOT claim to know who physically sent the email.
  • It will NOT claim the IP geolocation is the attacker's exact location.
  • It will only say: "The observed mail infrastructure is approximately geolocated to this region."
  • This keeps the project technically honest and legally defensible — important for a forensics tool.

Phase-by-Phase Build Plan

6 phases, ordered by dependency. Each phase produces something you can run and test before moving to the next.

Phase 1
Project Foundation & Email Parsing Engine
Backend scaffolding + core email parsing + database setup
  • Set up Python + FastAPI project — folder structure, virtual environment, dependencies
  • Set up MongoDB — local instance + connection, define collections (cases, analyses)
  • Build Module 1 — Email Parser — parse .eml files, extract headers, body, URLs, attachments
  • Build Module 2 — Header Forensics — detect Reply-To mismatch, routing anomalies, suspicious relays
  • Build Module 3 — SPF/DKIM/DMARC Analysis — parse Authentication-Results header, flag failures
  • Build Module 12 — Evidence Preservation — SHA-256 hash, Case ID generation, upload timestamp storage
  • Expose REST API endpoints — POST /upload, GET /case/:id
  • Write test .eml files — sample phishing + legitimate emails to test parsing
✓ Deliverable: Working backend that parses any .eml and returns structured JSON
Phase 2
AI / ML Threat Detection Model
Train phishing classifier + integrate into backend pipeline
  • Acquire training dataset — use public phishing email datasets (SpamAssassin, Enron, PhishTank CSV)
  • Preprocess emails with NLP — tokenization, stop-word removal, TF-IDF vectorization using NLTK/scikit-learn
  • Train classification model — Naive Bayes or Random Forest, evaluate accuracy/precision/recall
  • Build Module 4 — AI Detection — load trained model, classify email body, return label + confidence %
  • Save trained model to disk — using joblib/pickle so it loads on server startup without retraining
  • Integrate into analysis pipeline — called automatically after parsing
✓ Deliverable: Backend classifies uploaded email as PHISHING/LEGITIMATE with confidence score
Phase 3
URL, Domain & IP Intelligence
Modules 5, 6, 7 — external intelligence gathering
  • Build Module 5 — URL Analysis — extract URLs, check length, HTTPS, login keywords, lookalike patterns, IP-based URLs
  • Build Module 6 — Domain Intelligence — use dnspython to query A/MX/NS/TXT records for each suspicious domain
  • Build Module 7 — IP Intelligence — extract IPs from Received headers, call ip-api.com (free) to get country/ISP/ASN
  • Build Module 8 — Threat Correlation — find shared IPs between domains, URLs, and routing headers
  • Build Module 9 — Risk Scoring — weighted scoring formula combining all module outputs into a 0-100 score with explanation list
  • Extend API — full analysis results returned in one GET /analysis/:caseId response
✓ Deliverable: Complete analysis pipeline — every module runs end-to-end on one .eml upload

How to Use the Final Platform

  1. Open the web application in your browser.
  2. Log in with your analyst credentials.
  3. Click "Upload Email" and select a .eml file (any suspicious email saved from an email client).
  4. The system automatically runs all 13 modules in the background (takes a few seconds).
  5. You are redirected to the Investigation Dashboard showing the full analysis result.
  6. Review the risk score, classification, authentication failures, suspicious URLs, and IP intelligence.
  7. Zoom into the map to see approximate geolocation of mail infrastructure.
  8. Click the Investigation Graph tab to see how all indicators are connected.
  9. Click "Generate Forensic Report" to download a PDF containing the complete investigation.

Why This Project Matters

Email phishing is the #1 initial attack vector in cybersecurity. Most organizations rely on manual investigation or expensive commercial tools. This platform demonstrates how AI, NLP, network forensics, and infrastructure intelligence can be combined into an open, explainable, investigative assistant that any analyst can use — making it both a strong academic project and a realistic prototype of a real security product.
